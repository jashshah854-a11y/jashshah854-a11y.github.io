Setting up the bench

Ask better.
The answer gets simple.

Most hard problems are hard because the question is too wide. Change the mesh and the pour changes what it keeps.

A big question lets everything through.

How do we automate support? Nobody can answer that. So every message pours straight through, and all you are left holding is the pile.

A small question has one answer.

Same inbox. Which team should get this message? Every message has exactly one answer. The mesh closes and one thing stays.

Four wins on paper. Four rejections.

My optimizer kept improving my skills. Its own scores said they got better. I rejected all four. Each had quietly lost its back half. So I asked the wide question.

What did it actually see?

Only the first 3,000 characters of each skill. So every improvement quietly deleted the back half. Lifting that one cap fixed the loop.

The perfect number was two errors.

In my Launchboard demo, ad spend read 99% of plan. It looked perfect. Is the math wrong? Dead end. Is anything cancelling out? One flight 15.7% over, another 27.0% under.

Wrong questions ask about the outcome.

Pick one. Each step asks about the input, the boundary, or what changed, until the mesh keeps something.
